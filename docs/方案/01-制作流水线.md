# 01 制作流水线：从 SRT 到双比例 MP4

> 输入固定为：`final.txt` + `audio.wav` + `subtitles.srt`（+ 可选 `map.json` / `outline.json`）。
> 原则：**音频不动；SRT 只提供时间；文字以稿子为准；AI 只出 JSON。**

## 0. 目录

```text
episodes/<书名-日期>/
  final.txt                口播稿（唯一文字基准）
  audio.wav                已完成的配音
  subtitles.srt            已有字幕（时间来源）
  map.json                 可选：故事地图
  outline.json             可选：六段大纲
  video/
    sentences.json         句子表（id + start/end + 稿子文本）
    video_plan.json        视觉导演输出
    cards/                 程序排版卡 PNG
      V01_9x16.png
      V01_16x9.png
      ...
    subs/
      subtitles_9x16.ass
      subtitles_16x9.ass
      subtitles.srt        外挂字幕
    segs/                  分段视频（可断点重渲染）
      V01_9x16.mp4
      ...
    preview/
      preview_9x16.mp4     30 秒样片
      preview_16x9.mp4
    out/
      video_9x16.mp4
      video_16x9.mp4
      thumb_9x16.png
      thumb_16x9.png
    render_manifest.json
```

## 1. SRT 入库检查（程序 30 秒）

### 1.1 五项检查

| # | 检查 | 判定 | 不通过 |
|---|---|---|---|
| 1 | 编码 | UTF-8（含 BOM 可接受）；GB18030 自动转 | 转码后再跑 |
| 2 | 时间格式 | `00:00:00,000 --> 00:00:00,000`，逗号毫秒 | 修正格式 |
| 3 | 总时长 | 最后一条 end 与 WAV 总时长差 ≤2 秒 | 报错，先查 SRT/WAV 是否同一版 |
| 4 | 结构 | 无重叠、无空条、无单字行、每条 ≤2 行 | 自动修或标红 |
| 5 | 文字 | 抽 10 条与 `final.txt` 比对，人名/书名/数字优先 | 以稿子为准替换文本 |

### 1.2 文字校正（关键）

SRT 若是语音识别生成的（剪映常见），时间可信、文字可能有同音错字。**不要逐条独立模糊匹配**——重复句、数字（1998 vs 一九九八）、多行 cue 会误伤。

做法：**全局单调对齐**。

1. 两边都归一化：去空白、统一全半角、去标点；数字保留但单独标记。
2. 把 `final.txt` 和 SRT 全文拼成两条长串，做**全局单调对齐**（`difflib.SequenceMatcher` 或 DP），不允许跨条回跳。
3. 用对齐结果把每条 SRT 映射到稿子的字符区间，再按 `final.txt` 的句子边界切成 `S001…`。
4. 匹配成功：**保留 SRT 的 start/end，文本换成稿子里的句子。**
5. 一条 SRT 覆盖多句：按稿子字数比例切时间；多句 SRT 对应一句：合并。
6. **全局匹配率 <70%**：停止自动替换，整份标 `needs_review`，让用户确认「SRT 和稿子是不是同一版」。
7. 匹配失败的单条：保留 SRT 原文并标 `needs_review`，不静默替换。

> 结果：字幕不会出现识别错字，时间仍然跟音频走。

### 1.3 断句规则

- 单条 <0.8 秒：与相邻条合并。
- 单条 >6 秒：在逗号/分号处切；没有标点就按字数比例切。
- 单行最多：9:16 16 个汉字；16:9 22 个汉字。
- 不出现「单字成行」「最后一行只有一个标点」。

## 2. `sentences.json`

```json
{
  "episode": "书名-2026-10-25",
  "audio_duration": 912.4,
  "sentences": [
    {"id": "S001", "start": 0.0, "end": 3.8, "text": "他第一次走进那座城的时候，身上只有半张地图。", "srt_index": 1},
    {"id": "S002", "start": 3.8, "end": 7.2, "text": "守塔人接过地图，没有抬头。", "srt_index": 2}
  ]
}
```

- `id` 按顺序 `S001…`，不跳号。
- `text` 必须来自 `final.txt`；标点保留。
- 时间单位秒，保留 2 位小数。
- 这是所有后续步骤的唯一时间依据。

## 3. `video_plan.json`

### 3.1 结构

```json
{
  "version": 1,
  "episode": "书名-2026-10-25",
  "brand": "{{brand}}",
  "style": "paper_ink_vermilion",
  "aspects": ["9:16", "16:9"],
  "scenes": [
    {
      "id": "V01",
      "type": "title_card",
      "from": "S001",
      "to": "S004",
      "hold_seconds": 4,
      "layout": "full",
      "column": "读懂",
      "author": "作者",
      "title": "《书名》",
      "line": "一句不超过 12 字的钩子",
      "source_refs": [],
      "motion": "fade",
      "transition": "fade",
      "image": null
    }
  ]
}
```

### 3.1b 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `V01…`，按顺序 |
| `type` | 是 | 八种之一 |
| `from` / `to` | 是 | 句子 id，闭区间 |
| `hold_seconds` | 是 | 卡片显示时长；到时切品牌背景，场景仍覆盖原句子。`0` = 整场（背景/插画用） |
| `layout` | 是 | `full`（整帧）或 `lower_third`（叠加在画面上，不挡字幕） |
| `motion` / `transition` | 是 | 见 3.3 |
| `source_refs` | 事实卡必填 | 内部事实编号；观众看不到 |
| `image` | V1-lite/V1 必填 | 插画文件路径；V0 为 null |
| `column` / `author` | 标题卡必填 | 栏目、作者；作者不明写「未标注」 |
| `title` / `line` | 是 | 标题/一句话，长度按 3.4 |
| `index` / `name` | 章节卡必填 | `01` + 章节名 |
| `quote` / `source` / `quote_type` | 金句卡必填 | 直引 `direct` 必须有人能看懂的出处；转述 `paraphrase` 标「转述」 |
| `characters` | 人物卡必填 | `[{"name":"","role":""}]`，最多 4 个 |
| `nodes` | 时间线卡必填 | `[{"label":"","detail":""}]`，最多 4 个 |

### 3.2 场景类型

| type | 用途 | 版式 | 建议 `hold_seconds` |
|---|---|---|---|
| `title_card` | 开场：书名 + 钩子 + 栏目 | 全屏 | 4（3–5） |
| `section_card` | 章节开始：编号 + 章节名 | 全屏 | 2.5（2–3） |
| `quote_card` | 金句/关键判断 | 全屏或下半屏 | 5（4–6） |
| `character_card` | 人物 + 身份 | 下三分之一 | 8（5–10） |
| `timeline_card` | 时间线/阶段 | 下三分之一或全屏 | 8（6–10） |
| `background` | 品牌底 + 轻微运动 | 全屏 | 整场 |
| `illustration` | AI 插画（V1） | 全屏 | 整场 |
| `end_card` | 尾卡：下期见 + 互动问题 | 全屏 | 5（4–6） |

- 卡片只显示 `hold_seconds`，之后切品牌背景；场景仍然覆盖它 `from/to` 的全部句子。
- `lower_third` 是**叠加**：底层仍是当前背景/插画，卡片从下方浮出，不切整帧。

### 3.3 硬规则（程序校验）

1. 场景按 `from/to` 覆盖全部句子，**不重叠、不跳句、不越界**；首场从 `S001` 开始，末场到最后一号结束。
2. 场景数量：V1-lite/V0 15 分钟 **7–10 个**；25 分钟 **11–13 个**；V1 10–16 个。
3. 除 `title_card`/`section_card`/`end_card` 外，单场 ≥2 秒；任何场景 ≤4 分钟。
4. `layout` 只能是 `full` 或 `lower_third`；`lower_third` 不挡字幕。
5. `motion` 只能是 `fade` / `slow_zoom_in` / `slow_zoom_out` / `pan_left` / `pan_right` / `none`；`transition` 只能是 `fade` / `none`。
6. 卡片文字：标题 ≤12 字，章节名 ≤8 字，人物 ≤4 个，时间线 ≤4 个节点。
7. 事实类卡片必须带 `source_refs`，只能引用 `map.json`/`outline.json` 里的内容；没有就留空，用背景。
8. **直引必须带人看得懂的 `source`**（如「第 31 章」「原书第三部分」），`source_refs` 只是内部编号；C 级来源只能 `paraphrase`，并标「转述」。
9. **不写秒数**；秒数由程序从 `sentences.json` 算。

## 4. 视觉导演提示词（一次调用）

```text
# 角色：15–25 分钟书籍解说视频的视觉导演

你不写文案，不写秒数，不写 FFmpeg。你只决定：这一期在哪些句子之间换画面、换什么画面、卡片上写什么。

## 输入

书名：{{book_title}}
栏目：{{column}}            # 读懂 / 听故事
风格：paper_ink_vermilion   # 墨、纸、朱砂；不要另起一套
句子表（带 id）：
{{sentences}}

故事地图/大纲（可选）：
{{map}}

## 输出

只输出合法 JSON，结构见下。scenes 必须覆盖全部句子，按顺序，不重叠。

## 规则

1. 首场 title_card 从 S001 开始；末场 end_card 到最后一号结束。
2. 场景数：V0 7–10 个；V1 10–16 个。不要每句都换。
3. 只在以下位置换画面：开场、章节开始、关键转折、金句、人物/时间线、结尾。
4. 卡片文字必须来自输入，不能新增人物、事件、结局、数字；事实卡带 source_refs。
5. 标题 ≤12 字；章节名 ≤8 字；人物 ≤4 个；时间线 ≤4 个节点。
6. 文学：环境、物件、剪影；网文：环境、剪影、符号；非虚构：信息卡。
7. 不确定的地方用 background，不要编画面。
8. V0 的 image 一律为 null；V1-lite 最多 4 个 image_prompt；V1 最多 8 个。

## 输出结构

{"version":1,"episode":"","brand":"{{brand}}","style":"paper_ink_vermilion",
 "aspects":["9:16","16:9"],"scenes":[
  {"id":"V01","type":"title_card","from":"S001","to":"S004","layout":"full",
   "title":"《书名》","line":"钩子","source_refs":[],"motion":"fade","image":null}
]}
```

## 5. 卡片渲染（程序）

- V0 用 **Pillow**：读固定模板 PNG（纸底/墨底），按卡片类型画文字；中文字体随程序打包（思源黑体 Medium / 思源宋体 SemiBold），不依赖系统字体。
- V1 复杂版式再换 HTML/CSS → PNG（Playwright）。
- 每张卡同时输出 9:16（1080×1920）和 16:9（1920×1080）两版；文字自动换行、自动缩字号，最小 28px；仍溢出就截断并标红。
- 卡片元素只允许：栏目名、编号、标题、一句话、折角、印章、细线。不要插画、不要二维码。
- 文字一律程序绘制，**不让绘图 AI 生成中文**。

## 6. 渲染

### 6.1 分段渲染

每场按 `from/to` 算出时长，生成一段 MP4：

```text
ffmpeg -loop 1 -i cards/V01_9x16.png -t 4.2 \
  -vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,zoompan=z='min(zoom+0.0004,1.06)':x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':d=1:s=1080x1920:fps=30" \
  -r 30 -c:v libx264 -pix_fmt yuv420p segs/V01_9x16.mp4
```

- 运动只做缓慢推近/平移；幅度 2–6%，不要快速切换。
- 每段渲染后 `ffprobe` 校验时长，差 >0.1 秒就重渲染。
- 16:9 用另一套分辨率和卡片，不裁 9:16。
- **`zoompan` 的 `d=1` 在部分 FFmpeg 版本不累积**：先渲染 3 秒试片，确认画面真的在动；不动就用 `d=<帧数>` 或改用 `scale+crop` 的时间表达式。
- concat 前所有分段必须是**同分辨率、同 fps、同 pix_fmt、同编码**；否则拼出来会花屏或时长错。

### 6.2 拼接 + 字幕 + 音频

**先算总长，再合成。不要无条件用 `-shortest`**（某段渲染失败时会截掉音频）。

```text
# 1) 算 segs 总时长，与 audio.wav 比较
# 2) 若视频短了：把最后一段延长到 audio_duration + 0.2 秒
# 3) 若视频长了：合成时用 -t audio_duration 截视频（不截音频）
ffmpeg -f concat -safe 0 -i segs/list_9x16.txt -i audio.wav \
  -vf "ass=subs/subtitles_9x16.ass:fontsdir=fonts" \
  -c:v libx264 -preset veryfast -crf 22 -pix_fmt yuv420p -r 30 \
  -c:a aac -b:a 192k -ar 48000 \
  -t <audio_duration> \
  out/video_9x16.mp4
```

- 音频从 WAV 转 AAC 是**转码**；要求「不裁剪、不变速、不变调、不改响度」，不是「原样拷贝」。
- 合成前先断言 `视频总长 >= 音频总长 - 0.2 秒`；不满足就延长最后一段，不允许 `-shortest` 兜底。
- 字幕烧录用 ASS（可控字体/字号/描边/边距）；同时导出 SRT 外挂。
- 字体目录 `fonts/` 随程序打包，避免换电脑字体缺失。

### 6.3 ASS 参数

| 项 | 9:16 | 16:9 |
|---|---|---|
| PlayRes | 1080×1920 | 1920×1080 |
| Fontsize | 64（60–68） | 64（60–68） |
| MarginV | 260（240–280） | 120 |
| MarginL/R | 80 | 120 |
| Outline | 2 | 2 |
| Shadow | 0 | 0 |
| Alignment | 2（底部居中） | 2 |
| 行数 | 1–2 行 | 1 行优先 |

- 字体：Noto Sans SC Medium / 思源黑体 Medium；白色 + 2px 深色描边。
- 不用逐字弹出、花字、emoji。

## 7. CLI 契约（先独立，后接 UI）

```text
python -m video_engine check   --episode episodes/书名-日期
python -m video_engine plan    --episode ... --preset v1lite   # v0 / v1lite / v1
python -m video_engine cards   --episode ...
python -m video_engine render  --episode ... --aspect both --preview 30
python -m video_engine render  --episode ... --aspect both
python -m video_engine qc      --episode ...
```

- `check`：跑 SRT 五项检查，产出 `sentences.json`。
- `plan`：调视觉导演，产出 `video_plan.json`；失败重试 1 次。
- `cards`：只渲染缺失/变更的卡片（按 hash）。
- `render --preview 30`：只渲染开头 30 秒 + 一个章节 + 结尾，双比例。
- `qc`：跑质检清单，输出 `qc_report.json`。

## 8. `render_manifest.json`

```json
{
  "template_version": "v0.1",
  "fonts": {"NotoSansSC-Medium": "sha256:..."},
  "cards": {"V01_9x16": "sha256:..."},
  "inputs": {"final.txt": "sha256:...", "audio.wav": "sha256:...", "subtitles.srt": "sha256:..."},
  "outputs": {"video_9x16": {"duration": 912.4, "sha256": "..."}},
  "ffmpeg_commands": ["..."]
}
```

用途：同一输入同一输出；改一张卡只重渲染相关段；出问题能复现。

## 9. 依赖

- Python 3.12
- FFmpeg（含 libass、libx264、AAC）
- Pillow（V0 卡片）
- 字体文件：Noto Sans SC Medium、Noto Serif SC SemiBold（OFL，可商用）
- 可选：Playwright（V1 复杂卡片）、WhisperX（无 SRT 时兜底）

不需要 Node、不需要 n8n。

## 10. 失败处理

| 情况 | 处理 |
|---|---|
| SRT 缺失/损坏 | 停止，提示「先补 SRT」；不要猜时间 |
| SRT 末条与 WAV 差 >2 秒 | 停止，查是否同一版音频 |
| 某条 SRT 匹配不上稿子 | 保留 SRT 文本，标 `needs_review`，继续渲染 |
| 卡片文字溢出 | 自动缩到最小 28px；仍溢出则截断 + 标红 |
| 图片缺失（V1） | 用品牌底兜底，记日志 |
| 某段渲染失败 | 重试 1 次；仍失败保留该段占位，其他段继续 |
| 视频比音频短 | 最后一段延长到音频结束；不裁音频 |
| 视频比音频长 | `-shortest` 截视频；不裁音频 |
