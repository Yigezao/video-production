# 03 首期 Runbook：从 WAV + SRT 到可发布视频

> 你现在有：`final.txt` + `audio.wav` + `subtitles.srt`。
> 目标：**先出 30 秒双比例样片，再出全片。** 第一次搭模板 1–2 小时，之后每期 30–45 分钟（首期 V1-lite 4 张图）。

## 0.0 本次实测（羊脂球第一段）

路径：`D:\my_Software\Audacity\导出音频\羊脂球`

| 项 | 结果 |
|---|---|
| WAV | 48kHz / 立体声 / 16bit / **23.632 秒** |
| SRT | 15 条；最后一条结束 23.500 秒；与 WAV 差 **−0.132 秒** |
| 结构 | 无重叠、无 <0.8 秒、无 >6 秒、无单字行；最长 16 字 |
| 文字 | 去标点后与 `第一段.txt` **完全一致** |
| 结论 | **入库检查通过**；但这是 23.5 秒的测试段，不是完整一期 |

- SRT 是剪映生成的，这次文字没出错；以后若用语音识别生成，仍按「SRT 时间 + 稿子文字」校正。
- 23.5 秒测试段最多放 1 张图；**4 张图留给完整一期**，放在开场、第一次转折、至暗、高潮。

## 0. 目录与前置

```text
episodes/<书名-日期>/
  final.txt
  audio.wav
  subtitles.srt
  map.json          # 可选
  outline.json      # 可选
  video/            # 程序生成
```

前置：

- [ ] FFmpeg 可用（`ffmpeg -version`）。
- [ ] Python 3.12 可用。
- [ ] 字体文件：Noto Sans SC Medium、Noto Serif SC SemiBold 放进 `fonts/`。
- [ ] 账号昵称未定不影响；模板用 `{{brand}}`。

## 1. 第一步：SRT 入库检查（2 分钟）

让 AI 执行：

```text
python -m video_engine check --episode episodes/书名-日期
```

程序会输出：

- `sentences.json`：句子表；
- `check_report.json`：五项检查结果。

人工只看三件事：

- [ ] 最后一条字幕的结束时间 ≈ WAV 总时长（差 ≤2 秒）。
- [ ] 抽 5 条字幕，人名/书名/数字对得上稿子。
- [ ] 没有单字行、没有超过 6 秒的长条。

有问题先修 SRT；**不要带着错误时间往下走**。

## 2. 第二步：视觉导演（5 分钟）

```text
python -m video_engine plan --episode episodes/书名-日期 --preset v1lite   # 首期 4 张图
```

输出 `video_plan.json`。人工只验：

- [ ] 场景数 7–10 个；
- [ ] 第一场从 S001 开始，最后一场到最后一号结束；
- [ ] 没有跳句/重叠；
- [ ] 每张卡片的话都来自稿子；
- [ ] 没有「每句都换画面」。

不满意就改 `video_plan.json` 里的 `from/to` 或卡片文字；不用重跑 AI。

## 3. 第三步：卡片 + 30 秒样片（10 分钟）

```text
python -m video_engine cards  --episode episodes/书名-日期
python -m video_engine render --episode episodes/书名-日期 --aspect both --preview 30
```

- 音频短于 30 秒时，`--preview 30` 自动改为全片（如这次的 23.5 秒测试段）。
- 预览只渲染「开头 + 一个章节 + 结尾」；不是整片。

得到：

```text
video/preview/preview_9x16.mp4
video/preview/preview_16x9.mp4
```

人工看四处：

- [ ] 开头 3 秒：书名/钩子出现，没有「大家好」。
- [ ] 字幕：字号够大，不挡画面，不出安全区。
- [ ] 一个章节卡：不糊、不超框、停留 2–3 秒。
- [ ] 结尾 5 秒：尾卡完整，不黑屏。

**这一步不过，不要渲染全片。**

## 4. 第四步：全片渲染（8–15 分钟，按机器实测）

```text
python -m video_engine render --episode episodes/书名-日期 --aspect both
```

输出：

```text
video/out/video_9x16.mp4
video/out/video_16x9.mp4
video/out/subtitles.srt
video/out/thumb_9x16.png
video/out/thumb_16x9.png
```

## 5. 第五步：质检（5 分钟）

```text
python -m video_engine qc --episode episodes/书名-日期
```

人工再抽查：

- [ ] 时长与 WAV 差 <0.2 秒。
- [ ] 没有黑帧、静音尾巴、图片提前结束。
- [ ] 字幕抽查 10 条，偏差 <0.5 秒。
- [ ] 9:16 / 16:9 字幕都在安全区。
- [ ] 音频内容和原 WAV 一致（没有裁切/加速/变调）。
- [ ] 卡片人名、书名、数字与稿子一致。
- [ ] 缩略图大字在手机上看清。

## 6. 第六步：发布

- [ ] 上传 9:16 到抖音、16:9 到 B站。
- [ ] 简介带「本期文案与配音由 AI 辅助生成」；发布页勾 AI 声明。
- [ ] 标题 3 选 1；不剧透结局。
- [ ] 置顶评论：`本期《书名》。下期想听哪本？`
- [ ] 记录：时长、2 秒跳出、平均播放、涨粉、评论。

## 7. 首期：V1-lite（4 张图）

- 4 张图固定放在：开场标题之后、第一次重大转折、至暗、高潮/结局前。
- 每张停留 30–90 秒，缓慢推近/平移；其余段落用品牌底 + 卡片。
- 图片统一 1:1 或 4:3，主体居中，两个比例都能裁。
- 人物优先背影/剪影/环境，不生成正脸特写。
- 每张图先写 3 个候选 prompt，选最稳的；失败就用品牌底兜底。
- 图片生成失败或当天没时间：**直接退回 V0 发布**，不要卡住。

## 8. V0 / V1-lite 对比（10 期）

- 首期用 V1-lite；从第 2 期起 **交替**：V1-lite / V0 / V1-lite / V0… 各 5 期。
- 也可以前后各 5 期；交替更能抵消时间和选题差异。
- 尽量配对同类型、同长度的书（文学配文学，网文配网文）。
- 每期记录：时长、2 秒跳出、平均播放、涨粉、评论。

| 指标 | 长期采用 V1-lite 的条件 |
|---|---|
| 平均播放时长 | 比 V0 的 5 期中位数高 ≥15% |
| 2 秒跳出 | 不高于 V0 |
| 涨粉/千播放 | 不低于 V0 |
| 每期人工 | ≤60 分钟 |

四条都满足才长期用 V1-lite；否则留 V0，把时间花在选题和文案上。10 期后再考虑 V1（6–8 张图）。

## 9. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 字幕整段偏移 | SRT 与 WAV 不是同一版 | 重新导出 SRT；不要手动挪 |
| 某些字变方框 | 字体缺字/未打包 | 换 Noto Sans SC；检查 fonts 目录 |
| 卡片文字溢出 | 文案太长 | 缩字号/改短；程序标红的那张重渲染 |
| 视频末尾黑屏 | 最后一段短于音频 | 延长最后一段；不要裁音频 |
| 9:16 主体被裁 | 插画主体不居中 | 重新生成 1:1 居中图；或改用背景 |
| 渲染很慢 | 4K/高码率/长图 | 1080p、CRF 20、30fps；分段渲染 |
| 字体发虚 | 缩放/码率低 | 提高源图分辨率；CRF 18–20 |
