# 视频制作方案 V1.0-final

> 一句话：**音频和 SRT 已经定了，视频引擎只做三件事：解析 SRT → 设计画面 → 渲染。V0 先不上 AI 图。**
> 输入：`final.txt` + `audio.wav` + `subtitles.srt`（+ 可选 `map.json` / `outline.json`）。
> 输出：抖音 9:16 MP4、B站 16:9 MP4、外挂 SRT、封面图、渲染清单。
> 版本：V1.0-final（2026-10-25）。讨论记录见 `AI2_视频意见.md`。

## 0. 结论速查

| 项 | 定稿 |
|---|---|
| 首期形态 | **V1-lite：4 张 AI 图 + 7–10 张程序排版卡**（用户已定） |
| 时间基准 | **SRT + WAV**；不做语音识别，不重做音频 |
| 字幕 | ASS 烧录 + 另出 SRT；字号 9:16 60–68px、16:9 60–68px |
| 比例 | 9:16 与 16:9 **两套模板**，同一份 plan 驱动，不做裁切 |
| 渲染 | Python + FFmpeg；先独立 CLI，跑通 3 期再接 UI |
| 视觉 | 沿用账号的墨/纸/朱砂；品牌名用 `{{brand}}` 占位 |
| 升级 | 3 期后 V1（6–8 张图）；10 期后 V2（8–12 张 + 更强排版） |
| 验收 | 30 秒双比例样片先过，再全片 |

## 1. 三档视频，不要一步到位

| 版本 | 画面 | 每期人工 | 什么时候做 |
|---|---|---|---|
| **V1-lite（首期）** | 4 张 AI 插画 + 7–10 张程序卡 + 字幕 | 30–45 分钟 | **现在** |
| **V0** | 0 张 AI 图；品牌底 + 字幕 + 7–10 张卡 | 10–20 分钟 | 没时间/没图/想先跑通时 |
| **V1** | 6–8 张 AI 图 + 2–4 张信息卡 | 40–60 分钟 | 3 期后稳定 |
| **V2** | 8–12 张图、人物/场景设定、可选 Remotion | 1–2 小时 | 10 期后，数据证明值得 |
| V3 | AI 视频片段 | 不建议 | 暂不做 |

V0 不是「凑合版」：它把字幕、时间轴、双比例、章节节奏全部跑通。V1-lite 只加 4 张图，不改骨架。

**25 分钟以上的期**：场景数从 7–10 提到 **11–13**，否则画面更换太稀。

## 2. GPT 方案：留什么、改什么

| 留下 | 改掉 |
|---|---|
| 视频引擎与写稿/配音解耦 | 首版 10–18 张 AI 图 → 首期 4 张（V1-lite），V1 再 6–8 张 |
| AI 只出结构化镜头规划，不写 FFmpeg | 不默认 WhisperX；用户已有 SRT |
| 视频服从音频，绝不裁/加速音频 | 不改音频管线，不做分段 TTS |
| Python + FFmpeg 起步，Remotion 后置 | 去掉 n8n，调度就是读文件→调模型→跑 FFmpeg |
| 文学/网文/非虚构分策略 | 视觉改成账号的墨/纸/朱砂，不另起一套 |
| 分 V1/V2/V3 上线 | 增加 30 秒样片、渲染清单、SRT 入库检查 |

## 3. 架构

```text
输入：final.txt + audio.wav + subtitles.srt (+ map.json / outline.json)
        │
        ├─ ① SRT 入库检查
        │     时长对齐、文字校对、断句、格式
        ├─ ② 句子表 sentences.json
        │     每句 id / start / end / text
        ├─ ③ 视觉导演（一次 AI 调用）
        │     输出 video_plan.json：场景只引用句子 id，不写秒数
        ├─ ④ 素材
        │     程序排版卡（Pillow/HTML→PNG）；V1 才有 AI 插画
        ├─ ⑤ 渲染
        │     每场一段 MP4（图片 + 缓慢运动）→ 拼接 → ASS 字幕 → 音频
        ├─ ⑥ 质检
        │     时长、黑帧、字幕、安全区、首尾
        └─ 输出
               video_9x16.mp4 / video_16x9.mp4 / subtitles.srt
               thumb_9x16.png / thumb_16x9.png / render_manifest.json
```

## 4. 关键决策

1. **SRT 是唯一时间源。** 音频不动，视频时长 = 音频时长。
2. **文本以 `final.txt` 为准。** SRT 只提供时间；如果 SRT 文字和稿子不一致（同音错字），保留时间、换回稿子的句子。
3. **卡片有时长上限。** 卡片场景用 `from/to` 覆盖句子，但只显示 `hold_seconds`（标题 4s、章节 2.5s、金句 5s、人物 8s、结尾 5s）；剩余时间用品牌背景承接，不能为了凑满句子把卡片挂 20 秒。
4. **两套排版。** 9:16 与 16:9 的字幕字号、行宽、安全区、卡片位置分别计算；同一份语义 plan，不做裁切。
5. **AI 只做两件事**：选场景/写卡片文案；V1 时写插画 prompt。其余交给程序。
6. **先独立 CLI**：`video_engine/` 跑通 3 期，再加入现有 UI 的第 7 步；不先动主应用。
7. **可复现**：`render_manifest.json` 记录模板版本、字体哈希、卡片哈希、FFmpeg 命令；改一张卡只重渲染相关段。
8. **品牌占位**：账号昵称未定，卡片用 `{{brand}}`；栏目名「读懂 / 听故事」可直接用。

## 5. 一期的时间预算（V1-lite / V0）

| 步骤 | 首次 | 之后每期（V1-lite） | 之后每期（V0） |
|---|---|---|---|
| 搭模板 | 1–2 小时 | — | — |
| SRT 检查 + 句子表 | 10 分钟 | 2 分钟 | 2 分钟 |
| 视觉导演 + 卡片文案 | 15 分钟 | 10 分钟 | 5 分钟 |
| 4 张图生成/挑选 | — | 20–30 分钟 | — |
| 渲染 30 秒样片（双比例） | 10 分钟 | 3 分钟 | 3 分钟 |
| 全片渲染 | 10–20 分钟 | 8–15 分钟 | 5–10 分钟 |
| 人工看三处 + 发布 | 10 分钟 | 10 分钟 | 10 分钟 |

- 首期按 V1-lite 做，图片 4 张；没时间就退回 V0 直接发。
- 渲染时间按机器实测；首版先用 `-preset veryfast -crf 22`，别按理论值排期。

## 6. 验收标准

- 视频时长与 WAV 差 <0.2 秒；没有黑帧、静音尾巴、图片提前结束。
- 字幕与音频抽查 10 条，最大偏差 <0.5 秒；没有单字行、没有超 2 行。
- 9:16 / 16:9 都在安全区内；开头 3 秒有书名/钩子，结尾 5 秒有尾卡。
- 音频内容与原始 WAV 一致；没有为了画面裁切、加速、改音量。
- 卡片文字不超出边框；人名、书名、数字与稿子一致。
- 一条命令能重渲染；缺图时用品牌底兜底，不整期失败。

## 7. 风险

| 风险 | 处理 |
|---|---|
| SRT 是语音识别生成，有同音错字 | 文本以 `final.txt` 为准；抽 10 条人工核对 |
| 字幕太长/太碎 | 按逗号切；单条 0.8–6 秒；长条按字数比例拆 |
| 9:16 裁掉插画主体 | 插画统一 1:1/4:3，主体居中；V0 卡片原生排版 |
| AI 图人物不一致 | V1 先做视觉设定；多用剪影/环境；不生成正脸特写 |
| 渲染慢/黑屏 | 分段渲染 + concat；每段校验时长；失败段重渲染 |
| 账号名未定 | `{{brand}}` 占位；栏目名不依赖品牌 |
| 版权 | 不用原书封面/剧照；AI 图不模仿具体画师；引文合规 |
